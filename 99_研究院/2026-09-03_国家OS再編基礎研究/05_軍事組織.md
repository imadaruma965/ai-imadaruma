# 05 軍事組織 — AIエージェントの自律性設計

軍事組織は「不完全な情報」「時間圧」「分散した実行者」という、AIエージェント運用と同型の条件下で数世紀にわたり最適化されてきた。
本章はそこから、**AIにどこまで自律性を与えるか**の設計原理を抽出する。

---

## 1. Auftragstaktik / Mission Command【最重要】

[FACT / Evidence: HIGH]
19世紀プロイセン軍で体系化され、現代の米軍・NATO・自衛隊にも Mission Command として採用されている指揮哲学。

**中核構造**
- 上級指揮官は **「何を達成すべきか（What / Why）」** を伝える
- **「どうやるか（How）」** は現場に委ねる
- 現場は状況変化に対し、上位の意図の範囲内で自律的に判断する

**Commander's Intent（指揮官の意図）の3要素**（米陸軍 ADP 6-0 の定式）
1. **Purpose（目的）**: なぜこの作戦を行うのか
2. **Key Tasks（鍵となる任務）**: 目的達成に不可欠な行動
3. **End State（終了状態）**: 成功したとき、世界はどう見えるか

**成立条件（これが揃わないと機能しない）**[FACT / Evidence: HIGH]
- **共通のドクトリン**: 同じ言葉が同じ意味を持つこと
- **信頼**: 委任した判断を後から責めないこと
- **意図の明確な言語化**: 曖昧な意図の下では自律は暴走になる

[INTERPRETATION → AIエージェントへの転用]
**Auftragstaktik は、AIエージェント設計の最も適切な指揮モデルである。** 理由は3つ。

1. LLMは細かい手順指示に弱く、目的と制約の理解に強い。手順を全部書くなら、それはもうスクリプトであってAIを使う意味がない。
2. 状況は必ず変わる。手順指示は状況変化で無効になるが、意図は生き残る。
3. 手順を全部書くコストは、自分でやるコストとほぼ同じになる。

**しかし条件が厳しい。** 共通ドクトリンが無いままAIに自律を与えると、MAST（`11`参照）が指摘する「誤った前提での行動」が発生する。

[DESIGN → 指図書（Work Order）フォーマット]

AIエージェントへの依頼は、常にこの5項目で書く。

```
【目的】 なぜこれをやるのか（上位目標との接続）
【成果物】 何が出てきたら完了か（形式・分量・置き場所）
【制約】 やってはいけないこと・使ってはいけない手段・予算/時間の上限
【合格ライン】 これを満たせば十分（満足化。最適を求めない）
【権限】 L1〜L4 のどれか（`18`の意思決定レベル）
```

「どうやるか」は書かない。書きたくなったら、それは指図が不十分か、AIではなくスクリプトを書くべき仕事である。

## 2. OODA Loop

[FACT / Evidence: HIGH]
ジョン・ボイドによる意思決定サイクル。Observe → Orient → Decide → Act。

**しばしば誤解される点** [FACT / Evidence: HIGH]
ボイド自身の議論の中心は「速く回す」ことではなく **Orient（方向づけ）** にある。Orient は、観察結果を既存の文化的伝統・遺伝的継承・過去の経験・分析と統合して、世界の見方そのものを更新する段階である。ボイドの図では Orient から他の全段階へフィードバックが伸びている。

つまり **OODAの本体は「認識モデルの更新」であり、速度はその副産物**である。

[INTERPRETATION]
個人国家で最も欠けやすいのが Orient である。
- Observe（記録する）はできる
- Decide / Act（決めてやる）もできる
- **Orient（記録を見て、世界の見方を変える）が抜ける**

記録だけ溜まって認識が更新されない状態を、本研究では **「観測の死蔵」** と呼ぶ。ダヴィンチ図書館が567ノートを持ちながら国家戦略が変わらないなら、それは観測の死蔵である。

[DESIGN → Orient儀式]
週次に15分、次の1問だけに答える。
> **「今週わかったことのうち、来週の前提を変えるものは何か。1つ書け。無ければ『無し』と書け。」**

「無し」が4週続いたら、情報収集の質を疑う（外を見ていないか、見ても解釈していない）。

## 3. Staff System（幕僚制度）

[FACT / Evidence: HIGH]
プロイセン参謀本部に起源を持ち、NATO標準では次の機能番号で整理される。

| 番号 | 機能 |
|---|---|
| S1/G1 | 人事 |
| S2/G2 | **情報（Intelligence）** |
| S3/G3 | **作戦（Operations）** |
| S4/G4 | 兵站（Logistics） |
| S5/G5 | 計画（Plans） |
| S6/G6 | 通信 |

構造原理は2つ。
1. **指揮官は1人。幕僚は指揮しない。** 幕僚は分析・立案・調整を行うが、命令権を持たない。
2. **S2（情報）とS3（作戦）は分離される。** 作戦担当が情報も作ると、都合の良い情報になる。

[INTERPRETATION → 決定的な転用]
> **「幕僚は指揮しない」＝「AIは決定しない」。**
これはユーザーの第1項「AIは最終決定者ではない」と完全に一致する。軍事組織はこの原則を200年運用してきた実績がある。

> **S2/S3分離＝「情報エージェントと実行エージェントを分ける」。**
実行担当が自分の実行を正当化する情報を集めるのを防ぐ。これは `01` の「実行と検証の分離」と同型の原理が、情報側にも適用されるということ。

[DESIGN]
→ 情報・知識を扱うエージェントは、実行の管理をしてはならない。逆も同じ。

## 4. Intelligence Cycle（情報循環）

[FACT / Evidence: HIGH]
標準的な5段階（機関により4〜6段階）。

```
Direction（要求の設定）  ← 何を知りたいかを先に決める
   ↓
Collection（収集）
   ↓
Processing（処理・整形）
   ↓
Analysis & Production（分析・生産）
   ↓
Dissemination（配布）
   ↓ （新たな要求へ）
```

**この循環に対する定番の批判** [FACT / Evidence: MEDIUM–HIGH]
実務ではきれいな循環にならない。特に (a) Direction が曖昧なまま Collection が始まる、(b) Dissemination された情報が意思決定に使われない、という2つの断絶が頻発する。米インテリジェンス・コミュニティの改革論議でも繰り返し指摘されている。

[INTERPRETATION → 個人国家の情報活動の診断]
現行の情報活動（ルパンのリサーチ、ダ・ヴィンチの分析、note調査等）が機能しているかは、次の2点で判定できる。

1. **Direction はあるか。** 「調べておいて」で始まった調査は、Direction が無い。何を知れば何を決められるのかが先に無ければ、成果物は使われない。
2. **Dissemination の先で判断が変わったか。** 調査レポートを読んで戦略が1行も変わらなかったなら、その調査は消費であって投資ではない。

[DESIGN → 情報要求書（RFI）]
調査の起点に必ず置く。

```
【問い】 何を知りたいか（1文）
【これがわかると何を決められるか】 ← これが書けない調査はやらない
【判断期限】 いつまでに必要か
【十分条件】 どこまでわかれば調査を打ち切るか
```

**「これがわかると何を決められるか」が書けない調査は、着手を禁止する。** これは調査中毒（情報を集めること自体が目的化する状態）に対する唯一有効な予防策である。

## 5. After Action Review（AAR）

[FACT / Evidence: HIGH]
米陸軍で開発され、企業・医療にも広く移植された事後検討手法。核は4つの問い。

1. **What was expected to happen?**（何が起きるはずだったか）
2. **What actually happened?**（実際に何が起きたか）
3. **Why was there a difference?**（なぜ差が生じたか）
4. **What can we learn / do differently?**（次に何を変えるか）

**設計上の要点** [FACT / Evidence: HIGH]
- **非難しない（no-fault）**。責任追及の場にすると情報が隠される
- **短く、直後に**。時間が経つと記憶が再構成される
- **記録して次に使う**。AAR単体は無価値で、蓄積して初めて価値が出る

[INTERPRETATION]
問い1「何が起きるはずだったか」が本質である。これは事前に**予測が記録されていなければ答えられない**。
つまり AAR は事後の手法に見えて、**事前の予測記録を強制する仕組み**である。韓非子の「形名参同」、ドラッカーの「フィードバック分析」と完全に同じ構造。3つの独立した系譜が同じ結論に到達している。

[DESIGN → 個人国家のAAR]
1行版（日次・30秒）:
> 「予定 → 実際 → 差の理由」を1行ずつ。

正式版（週次・10分、または重要案件の終了時）:
> 上記4問。ただし**「次に何を変えるか」は1つだけ**書く。3つ書くと0つ実行される。

**AARの出力先が最重要**: 個別のログに埋もれさせず、`70_教訓/` へ蓄積する（`13`参照）。

## 6. Red Team

[FACT / Evidence: HIGH]
自軍の計画を、敵の視点あるいは批判的視点から攻撃する専門チーム。米軍のUFMCS（University of Foreign Military and Cultural Studies）等で体系化されている。

**主要技法**
- **Devil's Advocacy**: 意図的に反対の立場を取る
- **Pre-mortem**（Gary Klein, HBR, Tier B / Evidence: MEDIUM–HIGH）: 「この計画は1年後に大失敗した。なぜか？」を計画**実行前**に問う。事後の視点を借りることで、事前には言いにくいリスクが言語化される
- **Alternative Analysis / Team A–Team B**: 同じ情報から別の結論を出すチームを並走させる
- **Assumption Check**: 前提の明示と、その前提が崩れる条件の特定

[FACT / Evidence: MEDIUM]
Red Team が有効なのは **独立性が確保されている場合のみ**。計画者に従属する Red Team は儀式化する。これは `02` の門下省封駁権の空洞化と同じ現象。

[INTERPRETATION → AIにおける特殊事情]
**LLMは同意する方向に強いバイアスを持つ（sycophancy）。** したがって、
- 同じセッション内で「批判してください」と頼んでも、批判の質は低い
- 独立したコンテキストで、批判を役割として与えたときに初めて機能する

[DESIGN → Red Team は独立エージェントにすべきか]

**結論: 独立したAIエージェントにはしない。監査エージェントの「儀式」として実装する。**

理由:
1. `01`/`02` の教訓「小国で監査を複数置くと麻痺する」（宋）
2. Red Team は常時稼働の必要がなく、**特定の局面（新規参入・大きな支出・撤退判断）でのみ必要**
3. 監査エージェントと Red Team は「基準に照らして疑う」という同一機能。対象が過去（監査）か未来（Red Team）かの違いにすぎない

実装:
> 監査エージェントに **「プリモータム」モード** を持たせる。L3以上の意思決定の前に必ず1回起動し、次を出力させる。
> - この計画が失敗するとしたら、最も可能性の高い理由3つ
> - この計画が依存している、明示されていない前提2つ
> - 撤退すべきサイン1つ

## 7. 自律性の設計 — どの階層まで自律を与えるか

[DESIGN]
軍事組織の知見を統合すると、自律性は**不可逆性**と**外部性**の2軸で決まる。

```
                  外部に影響する
                        ↑
        L3 承認必須      |      L4 君主のみ
   （発信・提案・返信）   |  （契約・公開・支出・提携）
                        |
  ──────────────────────┼──────────────────────→ 不可逆
                        |                        （元に戻せない）
        L1 自動実行      |      L2 事後報告
   （調査・整理・下書き） |  （ファイル整理・記録更新）
                        |
```

| レベル | 内容 | 判定基準 | 例 |
|---|---|---|---|
| **L0** | 自動（AI判断なし） | 完全に定型 | 数値集計、ログ整形、リンク検査 |
| **L1** | AI自動実行 | 可逆・内部のみ・30分以内 | 調査、要約、下書き、整理案の作成 |
| **L2** | AI実行→事後報告 | 可逆・内部・ファイル変更を伴う | 台帳更新、ノート整理、テンプレ適用 |
| **L3** | AI提案→君主承認→実行 | 外部に出る／少額の支出 | SNS投稿、応募文、見積、価格提示 |
| **L4** | 君主のみ | 不可逆／高額／国家の同一性に関わる | 契約、新規事業開始、撤退、憲法改正、エージェント新設廃止 |

**Auftragstaktik との接続**: L1・L2 では「どうやるか」を指示しない。L3・L4 では君主が How にも関与してよい。

## 8. 本章の結論

1. **Auftragstaktik（意図＋制約を与え、方法は委ねる）がAIエージェント指揮の正しいモデル。** ただし共通ドクトリンと明確な意図が前提。
2. 指図書は **目的／成果物／制約／合格ライン／権限** の5項目。How は書かない。
3. **OODAの本体は Orient（認識更新）**。記録だけ増えて認識が変わらない「観測の死蔵」が最大のリスク。週次15分の Orient 儀式を置く。
4. **幕僚は指揮しない＝AIは決定しない。** 200年の実績を持つ原則。
5. **S2（情報）とS3（作戦）を分離する。** 実行担当に情報収集をさせない。
6. **調査は Direction から始める。「これがわかると何を決められるか」が書けない調査は禁止。**
7. **AAR の本質は事前の予測記録の強制。** 韓非子の形名参同、ドラッカーのフィードバック分析と同一構造。
8. **Red Team は独立エージェントにせず、監査エージェントのプリモータム儀式として実装する。**
9. 自律性は **不可逆性 × 外部性** の2軸でL0〜L4に決める。
