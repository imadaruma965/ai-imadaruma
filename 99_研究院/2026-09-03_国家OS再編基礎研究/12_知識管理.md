# 12 知識管理 — 手法の比較と、国家図書館への適用

Personal Knowledge Management（PKM）の主要手法を比較し、**個人国家の長期記憶**として何を採るかを決める。

---

## 1. 主要手法の比較

| 手法 | 中核思想 | 強み | 弱み | 個人国家への適合 |
|---|---|---|---|---|
| **Zettelkasten** | 1ノート1アイデア。ノート間をリンクし、思考が創発する | 知識が結合し、新しい発想が生まれる。長期の複利効果 | 立ち上げが遅い。**行動に直結しない**。厳密な運用は重い | **部分採用**（原則ノートに） |
| **PARA** | Projects / Areas / Resources / Archives の4分類。**行動可能性**で分類 | 実務直結。判断が速い。整理が単純 | 知識の結合が起きにくい。Resourcesが物置になる | **部分採用**（国家OS側に） |
| **Evergreen Notes** | ノートを継続的に育てる。concept-oriented、宣言的タイトル | 知識が精錬される。再利用性が高い | 手間がかかる。全ノートには適用できない | **中核採用** |
| **Second Brain (CODE)** | Capture / Organize / Distill / Express | パイプラインが明快。表現（Express）まで含む | Organizeの基準がPARA依存 | **パイプラインを採用** |
| **Knowledge Graph** | ノードとエッジで知識を表現 | 関係の可視化、検索性 | 個人規模では過剰。維持コスト | 概念のみ採用 |
| **Semantic Network / MOC** | Map of Content によるハブノート | 索引が人間的で使いやすい | MOCの維持を怠ると陳腐化 | **中核採用** |
| **Digital Garden** | 未完成のまま公開し、育てる | 公開圧が質を上げる。発信と学習が統合 | 公開できない情報を扱えない | **部分採用**（発信との接続） |

---

## 2. 手法選択の判断基準

[INTERPRETATION]
PKM手法の選択は、**「何のために知識を持つか」**で決まる。

| 目的 | 適する手法 |
|---|---|
| 思考を発展させたい（研究者型） | Zettelkasten |
| プロジェクトを進めたい（実務者型） | PARA |
| 知識を再利用したい（教育者型） | Evergreen |
| 発信したい（発信者型） | Digital Garden / Second Brain |

**個人国家は上記の全てを必要とする。** したがって単一手法の純粋適用は不可。

[DESIGN → 目的別のハイブリッド]
> **知識の種類ごとに手法を変える。**

| 知識の種類 | 手法 | 具体 |
|---|---|---|
| **原則・思想**（永続） | Evergreen + Zettelkasten | 1ノート1主張、宣言的タイトル、相互リンク |
| **研究・調査**（準永続） | Evergreen（軽量版） | 出典・信頼度・検証日を必須に |
| **事例・教訓** | 定型フォーマット | AAR形式で蓄積 |
| **進行中の案件** | PARA の Projects | **図書館ではなく国家OS側に置く** |
| **原資料** | 保管のみ | 加工しない。参照元として保持 |
| **発信素材** | Digital Garden | 図書館から抽出して発信へ |

## 3. 3つの重大な失敗パターン

[FACT / Evidence: MEDIUM — PKM実務コミュニティで広く報告。Tier C–D だが一貫している]

### 失敗1: Collector's Fallacy（収集家の誤謬）
**保存することを、理解することと混同する。** ハイライト・クリップ・保存が増えるが、読み返されず、判断も変わらない。

[INTERPRETATION]
`05` の「観測の死蔵」、`08` の「生産性の錯覚」と同じ現象。**567ノートあることは、567の知識があることを意味しない。**

[DESIGN → 対策]
> **ノート作成の関門: そのノートは (a) 国家OS側の生きた問いに答えるか、(b) 将来の判断を変えうる主張を含むか。どちらでもなければ作らない。**
単なる面白い情報は、原資料フォルダに置いて、ノートにはしない。

### 失敗2: 整理のための整理
フォルダ構造・タグ体系・テンプレートを磨くこと自体が目的化する。

[INTERPRETATION]
`08` の present bias（整理は楽しく、営業は苦しい）。**図書館の整理は、統治作業の中でも特に中毒性が高い。**

[DESIGN → 対策]
> **図書館の運用時間に上限を設ける（週◯分）。** 構造の変更は四半期に1回だけ許可する。

### 失敗3: 陳腐化の放置
古い情報が新しい情報と同じ見た目で残り続け、誤った判断の根拠になる。

[INTERPRETATION]
これが最も危険。**「SNSアルゴリズムは◯◯」という2年前のノートが、今日の判断に使われる。**
LLMエージェントメモリ研究（`11`）が指摘する **forgetting の欠如**と同じ問題。

[DESIGN → 対策]
> **全ノートに鮮度メタデータ（verified日、有効期限）を持たせ、期限切れを機械的に検出する。** 詳細は `13`。

## 4. 第27項「図書館の7機能」の設計

ユーザーが指定した7機能を、担当と頻度まで具体化する。

| 機能 | 内容 | 誰が | いつ | 成果物 |
|---|---|---|---|---|
| **Knowledge Acquisition** 獲得 | 外部情報の取り込み | 知（S4）＋君主の読書 | 随時 | 受信箱への投入 |
| **Knowledge Processing** 要約・整理 | 受信箱を処理し、1ノート1主張に分解 | 知 | **週次（受信箱ゼロ化）** | 研究ノート |
| **Knowledge Validation** 検証 | 出典のTier判定、信頼度の付与、反証の確認 | 知 | 処理と同時 | frontmatter の source_tier / confidence |
| **Knowledge Connection** 連結 | 既存ノートへのリンク付け、MOCへの登録 | 知 | 処理と同時 | **最低2リンク（これを満たさないノートは作らない）** |
| **Knowledge Application** 適用 | 国家OSへの反映 | 知 → 執行代理 | 週次 | **原則カード**（後述） |
| **Knowledge Updating** 更新 | 陳腐化したノートの再検証 | 知 | 週次の期限切れ検査 | verified日の更新 |
| **Knowledge Retirement** 廃棄 | 古い知識の退役 | 知 → 監が承認 | 四半期 | アーカイブへ移動（**削除しない**） |

**重要な設計判断:**
> **Connection を必須にする。「最低2つの既存ノートにリンクできないノートは作らない」。**
リンクできないということは、既存の知識体系に接続していないということ。それは孤立した情報であり、二度と参照されない。これは Zettelkasten の核心的規律である。

## 5. 第63項「国家OS と図書館の分離」【最重要】

[DESIGN — 本章の核心]

> **State OS ＝ 国家を動かす。可変・小さい・今の権威。**
> **Da Vinci Library ＝ 国家を賢くする。累積・大きい・時代を超える。**

この2つを混ぜると両方が壊れる。

| | State OS | 図書館 |
|---|---|---|
| **目的** | 決める・動く | 賢くなる |
| **内容** | 憲法、国家目標、戦略、台帳、今日の一手、決裁記録 | 原則、研究、事例、人物、原資料、教訓 |
| **サイズ** | **小さく保つ**（100ファイル以下） | 大きくてよい |
| **更新頻度** | 日次〜週次 | 週次〜随時 |
| **削除** | 積極的に廃止 | 削除せずアーカイブ |
| **正本性** | **今この瞬間の正解が1つ** | 複数の見解が並存してよい |
| **読み手** | 執行代理・監・君主 | 知・君主 |

### 境界を守る2つの通行証

両者は交流しなければ意味がないが、**無制限に交流すると境界が崩れる**。そこで、**2種類の成果物だけが境界を越える**と定める。

**通行証1: 決裁記録（Decision Record）— OS → 図書館**
```
【日付】【決めたこと】【選ばなかった選択肢】【前提】【予測】【見直す条件】【結果（後日追記）】
```
国家OSで決めたことは、決裁記録として図書館に流れる。図書館側では追記のみ（改変禁止）。
→ これが `04` 形名参同、`05` AAR、`07` メタ認知の共通の実装体である。

**通行証2: 原則カード（Principle Card）— 図書館 → OS**
```
【原則】1文で書ける行動指針
【根拠】図書館内のノートへのリンク（最低1）
【適用場面】どういう時に使うか（if-then形式）
【有効期限】
```
図書館の研究は、そのままでは国家OSに影響しない。**原則カードに凝縮されて初めてOS側に入る。**

> **[DESIGN] 週次の図書館運用の成果物は「原則カード0〜2枚」である。**
> 0枚でもよい。しかし3枚以上は多すぎる（実行できない）。

### 現行の境界侵犯 [実測]
現行 `05_情報省/ダヴィンチ図書館/` の中に:
- `90_国家OS保管/`（decisions, daily_logs, weekly_reviews, domain_ministries, governance_boards）— **これは国家OSの内容**
- `02_国家事業/`（Instagram, note, Player Statecraft）— **これは進行中のプロジェクト＝国家OS側**

**図書館が国家OSを飲み込んでいる。** これにより「今どちらが正本か」が不明になっている（`07` 外在的認知負荷、`01` 早期警戒指標5に該当）。

## 6. 第30項「国家知識循環」の設計

ユーザーが提示した循環を、実装可能な形に具体化する。

```
世界（外部）
  ↓ ① 情報要求書（RFI）で目的を先に定める
情報収集（知）
  ↓ ② 受信箱へ投入（生のまま）
図書館・受信箱
  ↓ ③ 週次処理：検証 → 蒸留（1ノート1主張）→ 連結（最低2リンク）
図書館・研究ノート
  ↓ ④ 原則カードへ凝縮（週0〜2枚）
国家OS・原則
  ↓ ⑤ 戦略・政策へ反映（四半期の戦略会議）
国家戦略
  ↓ ⑥ 指図書として工房へ
行動
  ↓ ⑦ 結果を記録
決裁記録＋AAR
  ↓ ⑧ 図書館の教訓フォルダへ
図書館・教訓
  ↓ （①へ：教訓が次の情報要求を生む）
```

**このループが切れる典型的な箇所** [INTERPRETATION]

| 切れる箇所 | 症状 | 対策 |
|---|---|---|
| ① が無い | 目的なき調査。成果物が使われない | RFIを必須化。「何を決められるか」が書けない調査は禁止 |
| ③ が滞る | 受信箱が溜まる。情報が死蔵される | **週次の受信箱ゼロ化を必達にする** |
| ④ が無い | **最も多い断絶。** 研究は増えるが行動が変わらない | **原則カードを週次成果物として義務化** |
| ⑦ が無い | 結果が記録されず、学習が起きない | 決裁記録の「結果」欄を月次で埋める |
| ⑧ が無い | 教訓が個別ログに埋もれる | 教訓フォルダへの集約 |

> **④の断絶が最も致命的である。** ここが切れていると、図書館は国家を賢くしていない。ただの倉庫である。
> **図書館の唯一のKPIは「今月、判断を変えた原則カードの数」であるべき。** ノート数でも文字数でもない。

## 7. 第31項「AIと共通知識基盤」

[DESIGN]
ユーザーの問題設定は正しい。**知識の分断を防ぎたいが、全AIが全知識を読むとコンテキスト過負荷になる。**

`11` のコンテキスト断片化研究が示す通り、これはトレードオフである。解は「全部読ませる」でも「各自が持つ」でもない。

> **[DESIGN] 3層のコンテキスト供給。**

| 層 | 内容 | 誰が読むか | サイズ目安 |
|---|---|---|---|
| **共通憲章** | じぶん憲法の要約、第一国家目標、統治原則、意思決定レベル | **全エージェント必読** | 1ファイル・2000字以内 |
| **国情ブリーフ** | 今の国家状況（数字・進行中案件・今週の重心・未解決の警告） | **全エージェント必読** | 1ファイル・1500字以内、**週次更新** |
| **役務コンテキスト** | そのエージェントのロール定義、担当台帳、過去の対話ログ | **当該エージェントのみ** | 制限なし |

**キーポイント:**
- 分断を防ぐのは「共通憲章＋国情ブリーフ」の2ファイルだけで足りる。合計3500字程度
- **これが `10` の shared consciousness、`05` の Commander's Intent、`11` の症状4（同じことを何度も説明する）への統一的な解**
- 図書館の本体（567ノート）を全AIに読ませる必要はない。**検索で必要な時に引けばよい**

| **第一国家目標** | 国家OS／憲法 | **君主のみ（L4）** | |
| **国家戦略** | 国家OS／戦略 | 君主（L4）、執行代理が起草 | 現行は法の系統にあり要移動 |
| **政策・方針** | 国家OS／戦略 | 執行代理起草＋君主承認（L3） | |

**AIが正本を勝手に書き換えない仕組み** [第60項への回答]
1. **L4項目（憲法・国家目標・エージェント定義・運用ルール）はAIの書き込み権限を持たせない。** 提案は別ファイル（`提案/`）に出させる
2. **決裁記録は追記のみ。** 過去の記録を書き換えると学習が壊れる
3. **git を監査証跡として使う。** 現行が既にgit管理下にあるのは大きな資産
4. **図書館の原則ノートの改変は、監の検証を経る**

## 9. 第33項「Memory Architecture」の割当

[DESIGN]

| メモリ種別 | 内容 | 保存場所 | 更新頻度 | 誰が |
|---|---|---|---|---|
| **Constitutional Memory** | 憲法、価値観、七徳、第一国家目標 | 国家OS／憲法 | 年次 | 君主 |
| **Strategic Memory** | 戦略、重心、資源配分、やらない戦 | 国家OS／戦略 | 四半期 | 君主＋執行代理 |
| **Operational Memory** | 今日の一手、進行中案件、台帳 | 国家OS／日次・台帳 | 日次〜週次 | 執行代理 |
| **Episodic Memory** | いつ何を決めたか、何が起きたか | 図書館／決裁・教訓 | 随時（追記） | 執行代理→知 |
| **Knowledge Memory** | 原則、研究、事例 | 図書館／原則・研究・事例 | 週次 | 知 |
| **Relationship Memory** | 顧客・関係先・競合の情報 | 図書館／人物 | 随時 | 知 |
| **Financial Memory** | 収入・支出・現金・パイプライン | 国家OS／財政台帳 | 週次（自動） | 帳（自動化） |
| **Procedural Memory** | 手順、テンプレート、スクリプト | 国家OS／規格 | 随時 | 執行代理・匠 |
| **Self Memory** | 君主自身の傾向、七徳の評価履歴、体調パターン | 国家OS／君主 | 月次 | 監 |

**設計上の要点:**
- **Constitutional / Strategic は極小に保つ。** 大きくなると読まれなくなり、参照されない憲法は存在しないのと同じ
- **Operational は使い捨て。** 週次で圧縮し、意味のあるものだけ Episodic へ昇格
- **Episodic は追記のみ、削除しない。** ここが学習の源泉
- **Self Memory を明示的に持つ**（`11` の profile memory 研究に対応）。「自分はこういう時に判断を誤る」の蓄積が、最も価値の高いメモリになりうる

## 10. 本章の結論

1. **単一のPKM手法では足りない。知識の種類ごとに手法を変える**（原則＝Evergreen+Zettelkasten、案件＝PARA、教訓＝AAR定型）。
2. **3つの失敗パターン**: 収集家の誤謬／整理のための整理／陳腐化の放置。全て現行図書館に該当リスクがある。
3. **ノート作成の関門を設ける**: 生きた問いに答えるか、判断を変えうる主張を含むか。**最低2リンクを必須に。**
4. **State OS と図書館の境界は、2つの通行証（決裁記録・原則カード）でのみ越える。**
5. **現行は図書館が国家OSを飲み込んでいる**（`90_国家OS保管/`、`02_国家事業/`）。境界侵犯を解消する必要がある。
6. **知識循環で最も切れやすいのは「研究 → 原則カード」の④。** ここが切れると図書館はただの倉庫。
7. **図書館の唯一のKPIは「今月、判断を変えた原則カードの数」。** ノート数ではない。
8. **AIへのコンテキスト供給は3層**: 共通憲章（2000字）＋国情ブリーフ（1500字）＋役務コンテキスト。図書館本体は検索で引く。
9. **正本を項目ごとに1つ決め、L4項目はAIに書き込ませない。** git が監査証跡になる。
10. **Self Memory（君主自身の判断傾向）を明示的に持つ。** 最も価値の高いメモリになりうる。
