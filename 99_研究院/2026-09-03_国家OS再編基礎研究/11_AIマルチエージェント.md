# 11 AIマルチエージェント研究（2024–2026）

**本章は本研究で最も実務的な結論を含む。**
中心的検証課題は、ユーザーが第15項で指定した通り、**「AIエージェントを増やせば賢くなる」という仮説を否定的に検証すること**である。

本章の記述は 2026-09-03 時点のWeb調査で確認した公開研究に基づく。出典は末尾に記載。

---

## 1. 結論を先に

[FACT / Evidence: HIGH]
> **エージェントを増やしても賢くはならない。多くの場合、悪くなる。**
> 計算量を統制すると、単一エージェントがマルチエージェントに匹敵するか上回るという報告が複数モデルで一貫している。
> マルチエージェントが優位になるのは、**(a) 並列独立探索、(b) コンテキスト隔離、(c) 検証の独立性**という3条件のいずれかが該当する場合に限られる。

## 2. 実証研究 — 何が確認されているか

### 2.1 MAST: マルチエージェント失敗のタクソノミー

[FACT / Evidence: HIGH — Tier A]
"Why Do Multi-Agent LLM Systems Fail?"（arXiv:2503.13657、NeurIPS 2025 採録）

- 7つの主要MASフレームワークにわたる **1600件以上の注釈付きトレース**を分析
- **14の失敗モードを3カテゴリに分類**した最初の体系的タクソノミー（MAST）
- 注釈者間一致度 κ = 0.88（高い信頼性）

**3つの失敗カテゴリ**

| カテゴリ | 内容 |
|---|---|
| **(i) System design issues（システム設計の問題）** | 役割の不明確さ、仕様の曖昧さ、手順の欠落 |
| **(ii) Inter-agent misalignment（エージェント間の不整合）** | 誤った前提での行動、他エージェントの入力の無視、作業の重複 |
| **(iii) Task verification（タスク検証）** | 出力の検証を怠る、不十分な検証 |

**最も重要な発見** [FACT]
> **失敗の多くはモデル性能ではなく、システム設計に由来する。**
> プロンプト改善だけでは解決せず、構造的な再設計が必要。

さらに、production環境でのマルチエージェントLLMシステムの失敗率は **41〜86.7%** と報告されている。仕様の曖昧さと非構造的な調整プロトコルにより、エージェントが役割を誤解し、作業を重複させ、検証を飛ばす。

[INTERPRETATION → ai-imadaruma への直接適用]
MASTの3カテゴリは、現行構造の問題と1対1で対応する。

| MASTカテゴリ | 現行 ai-imadaruma での対応する問題 |
|---|---|
| (i) System design | 13体のエージェントの役割境界が曖昧。分割軸が混在（`10`参照） |
| (ii) Inter-agent misalignment | 対話ログが2箇所に分散し、エージェント間で状況認識が共有されない |
| (iii) Task verification | 監査（栄一）は存在するが、指摘への応答が制度化されていない |

### 2.2 計算量を統制した比較

[FACT / Evidence: HIGH]
複数の2025〜2026年の研究が、計算量（トークン消費）を統制した条件下で比較を行っている。

- 複数モデル（Qwen3、DeepSeek-R1-Distill-Llama、Gemini 2.5）にわたり、**計算量を統制すると単一エージェントがマルチエージェントに一貫して匹敵または上回る**
- マルチエージェントの報告された優位性の多くは、**アーキテクチャの本質的利点ではなく、計上されていない計算量とコンテキスト効果で説明できる**
- あるケースでは、マルチエージェントの相対的性能向上は **わずか4%** に対し、**計算コストは4倍**

[INTERPRETATION]
> **「マルチエージェントにしたら良くなった」の多くは、単に多くの計算を使っただけである。**
> 同じ計算量を単一エージェントに与えれば、同等の結果が得られる。

### 2.3 コンテキスト断片化（Context Fragmentation）

[FACT / Evidence: HIGH]
> マルチエージェントの調整は、分岐・後戻り・合意形成のオーバーヘッドを導入し、本来なら線形であるべき推論の連鎖を断片化する。
> **各引き継ぎにおいて、受け取る側のエージェントは、完全な推論トレースではなく圧縮された要約からコンテキストを再構成しなければならない。この再構成損失は各ステップで累積する。**

[INTERPRETATION → 個人国家への最重要含意]
これが、**エージェントを増やすほど賢くならない理由の中核メカニズム**である。

> エージェントAが持っていた文脈のうち、エージェントBに渡るのは要約だけ。
> 要約は必ず何かを失う。エージェントが多いほど、引き継ぎ回数が増え、損失が累積する。

そして人間側にも同じことが起きる。
> **君主が13体のエージェントに同じ背景を毎回説明し直しているなら、それはコンテキスト断片化の人間側の現れである。**
> ユーザーが第16項で挙げた「同じことを何度も説明する」は、この現象の正確な記述である。

### 2.4 マルチエージェントが勝つ条件

[FACT / Evidence: HIGH]
同じ研究群が、マルチエージェントが優位になる条件も特定している。

1. **推論の複雑度が高い領域**: 複雑度が上がると単一エージェントの性能は急速に劣化するが、マルチエージェントは維持される
2. **コンテキスト干渉の隔離**: 別のワーカーに分離することで、各ワーカーは関連トークンのみを受け取り、オーケストレーターは単一モデルが見るプロンプトを膨らませずに回答を再構成できる
3. **並列化可能な独立ストランド**: 広範なリサーチのように、独立に探索できる枝が複数ある場合

### 2.5 Anthropic の Research システム（実運用事例）

[FACT / Evidence: HIGH — Tier B/C]
Anthropic が 2025年4月にリリースした Research 機能の設計。

- **オーケストレーター–ワーカー型**: リードエージェントが計画し、**3〜5体の専門サブエージェント**を並列起動し、その結果を統合する。引用付与は別パスで行う
- 内部評価で単一エージェントの Claude Opus 4 を **90.2%** 上回った
- **ただしトークン消費は通常のチャットの約15倍**
- **トークン使用量が性能分散の80%を説明した**
- **広範な調査質問に適するが、コーディングのような密に相互依存するタスクには不向き**

[INTERPRETATION → 4つの含意]
1. **サブエージェントは3〜5体**。これは本研究が `01`（認知容量）、`02`（歴史）から独立に導いた「3〜5」と一致する
2. **性能向上の80%はトークン量で説明される** ＝ アーキテクチャの魔法ではなく、計算量を投じた結果
3. **15倍のコスト**は無視できない。個人国家の資源制約（`18` 国家予算）から見て、常時マルチエージェントは非現実的
4. **相互依存の強い作業には不向き**。個人国家の日常運営（今日何をするか）はまさに相互依存が強い。**したがって日常運営はマルチエージェントにすべきでない**

### 2.6 エージェント乱立のアンチパターン

[FACT / Evidence: MEDIUM–HIGH — Tier C]
2026年時点のエンタープライズ導入で、以下が確立されたアンチパターンとして認識されている。

- 役割の重複と、タスクカバレッジの欠落が同時に発生する
- 不明確な指示により、エージェントが作業を重複させ、重要な手順を飛ばし、役割を誤解する
- **ほとんどのアンチパターン（役割重複、メモリの散乱、ハルシネーションの伝播、オーケストレーションの破綻）は、LLM自体の誤用ではなく、ガードレールと説明責任を欠いた不十分に調整されたエージェント・エコシステムから生じる**

## 3. 第16項「エージェント乱立問題」への回答

ユーザーが挙げた8つの症状を、原因と対策に分解する。

| # | 症状 | 原因 | 対策 |
|---|---|---|---|
| 1 | AI AとAI Bの役割が似ている | 分割軸の不統一（機能別と領域別の混在） | **分割軸を機能別に統一。領域は台帳へ** |
| 2 | 同じ情報を複数AIが管理 | 正本（SSoT）が定義されていない | **項目ごとに正本を1つ決める** |
| 3 | 誰に聞けばよいか分からない | 入口が複数ある | **入口を1つに（執行代理が振り分ける）** |
| 4 | 同じことを何度も説明する | コンテキスト断片化 | **共通の国家状況ファイルを全エージェントが読む** |
| 5 | AIが異なる方針を出す | 共通ドクトリンの欠如。憲法が参照されていない | **全エージェントの起動時に憲法＋国家目標＋国情ブリーフを読む** |
| 6 | 更新されないAIが残る | 廃止がデフォルトでない | **有効期限＋四半期の戸籍調査** |
| 7 | 名前だけ存在するAIが増える | 新設が安すぎる | **定員制（新設には廃止か空き枠が必要）** |
| 8 | 組織図は立派だが使われない | 令外官化（`02` 律令制の教訓） | **使用実績の計測と、実績に基づく廃止** |

> **8症状のうち、5つ（1,2,3,6,7）は「構造」の問題であり、3つ（4,5,8）は「共有と計測」の問題である。**
> どれもモデル性能の問題ではない。これはMASTの結論（失敗はシステム設計に由来する）と一致する。

## 5. エージェントを追加してよい条件（3条件テスト）

[DESIGN — 本研究の中核的判定基準]

研究結果から、エージェント追加が正当化されるのは次の**いずれか**に該当する場合のみ。

### 条件A: 並列独立探索
複数の独立した枝を同時に探索でき、結果を統合できる。
- 該当例: 広範な市場調査、複数の競合の同時分析
- **非該当例**: 今日の予定を決める（相互依存が強い）

### 条件B: コンテキスト隔離
そのタスクが大量の専用コンテキストを必要とし、他の作業のコンテキストを汚染する。
- 該当例: コードベースの作業、大量の一次資料の読解、ブランドのビジュアル資産
- **非該当例**: 一般的な相談

### 条件C: 検証の独立性
自己検証がバイアスを持つため、独立した主体が必要。
- 該当例: **監査。これが最も強く正当化される単一の分離**
- 補足: `01`（唐の三省）、`05`（S2/S3分離）、`09`（VSM S3\*）、MASTの (iii) が全て同じ結論

**3条件のいずれにも該当しない場合、エージェントを追加してはならない。**
役割の違い・思想の違い・領域の違いは、追加の理由にならない。それらは**プロンプトの違い**であって**エージェントの違い**ではない。

> **[DESIGN] 「別の人格が欲しい」は、別のエージェントを作る理由ではない。** それは指図書の中の一行（「◯◯の観点から検討せよ」）で足りる。

## 6. メモリ整合性（Memory Consistency）

[FACT / Evidence: MEDIUM–HIGH]
2026年時点のLLMエージェントメモリ研究の到達点。

- メモリアーキテクチャの3つの基本プロセス: **統合（consolidation：いつ何を永続化するか）／構造化（structuring：どう組織化するか）／検索（retrieval：どう再活性化するか）**
- 長期メモリの管理操作: consolidation、indexing、updating、**forgetting（古い・誤った内容の除去）**
- 多層メモリ（working / episodic / semantic）に分解し、適応的ゲーティングと保持正則化を行うフレームワークが提案されている
- MemoryOS のような、短期・中期・長期の階層とプロファイルメモリを持つ構成

[INTERPRETATION → 個人国家のメモリ設計]
研究が示す最重要点は **forgetting が明示的な操作である**ということ。
> **忘れる仕組みを持たないメモリは、必ず劣化する。**

現行のダヴィンチ図書館は567ノートを持つが、**廃棄・退役の仕組みが明示されていない**。これはメモリ研究の観点から明確な欠陥である（`13`で設計する）。

[DESIGN → メモリ階層の対応]

| 研究上の分類 | 個人国家での実装 | 保存場所 |
|---|---|---|
| **Working memory** | 今日の一手、進行中の案件 | 国情ブリーフ（1ファイル） |
| **Episodic memory** | 何が起きたか、いつ何を決めたか | 決裁記録、AAR |
| **Semantic memory** | 一般化された知識・原則 | 図書館の原則・研究ノート |
| **Procedural memory** | 手順・テンプレート | 規格・テンプレート・スクリプト |
| **Profile memory** | 君主自身についての知識 | 君主.md、七徳の評価履歴 |
| **Forgetting** | 期限切れの退役 | アーカイブ（削除しない） |

## 7. ハルシネーション伝播と、三省制の有効性

[FACT / Evidence: MEDIUM–HIGH]
マルチエージェント系では、あるエージェントの誤りが下流のエージェントに伝播し、**下流のエージェントがそれを前提として扱うため、誤りが強化される**（MASTの (ii) inter-agent misalignment に含まれる）。

[INTERPRETATION → 第20項「中国三省制型」への回答]
ユーザーの提案:
```
Proposal Agent → Critic/Review Agent → Execution Agent
```

**評価: 部分的に有効。ただし条件付き。**

**有効な点** [Evidence: MEDIUM–HIGH]
- 独立した Critic は、自己検証のバイアスを回避する（条件C）
- 実行前に止める（唐の封駁）ため、誤りが実行段階に届かない

**注意点**
1. **Criticが独立したコンテキストを持たないと機能しない。** 同一セッション内で「批判して」と頼んでも、LLMの同意バイアス（sycophancy）により質が低い
2. **3段階は遅い。** `02` の唐・政事堂の教訓通り、コストが高いと飛ばされる
3. **全ての作業に三省制を適用してはならない。** L1/L2 の可逆な作業に審査を挟むのは純損失

[DESIGN → 三省制の限定適用]
> **三省制は L3 以上（外部に出る／不可逆／支出を伴う）にのみ適用する。**
> L1/L2 は起草＝実行で構わない。

```
L1/L2:  執行代理 → 実行
L3:     執行代理（起草） → 監（封駁チェック・5分） → 君主承認 → 実行
L4:     知（情報提供） → 監（プリモータム） → 君主決定 → 執行代理（実行管理）
```

## 8. 第7項「AI同士の上下関係は必要か」への回答

[DESIGN]
> **必要。ただし「命令」の上下ではなく「情報の流れ」の上下である。**

理由:
1. フラットなネットワークは調整コストが高い（`10`）
2. しかしAIが他のAIに命令する構造は、責任の所在を曖昧にする（幕僚は指揮しない、`05`）
3. 実際に必要なのは、**「誰が誰の出力を受け取り、誰に渡すか」の固定された経路**

[DESIGN → 正しい階層の形]
```
君主  ← 全ての決定
  ↑ 報告
執行代理（S3）  ── 工房へ指図書を出す（これは命令ではなく発注）
  ↑ 成果物
工房（S1）

監（S3*）  ── 執行代理をバイパスして君主へ直報。誰の指図も受けない
知（S4）   ── 執行代理と監の両方に情報を供給。誰も指揮しない
```

**重要**: 監と知は、執行代理の**部下ではない**。3体は君主に対して並列である。
上下があるのは「執行代理 → 工房」の一箇所だけ。

## 9. 第8項「AI同士の議論・反対意見・監査はどの程度必要か」への回答

[DESIGN]
> **議論は不要。反対意見は必要。監査は必須。**

| 項目 | 必要性 | 理由 |
|---|---|---|
| **AI同士の自由な議論** | **不要** | トークンを大量消費し、結論が収束しない。MASTの調整失敗の温床。個人国家の資源では贅沢すぎる |
| **構造化された反対意見** | **必要** | 確証バイアスと楽観バイアスへの唯一の対抗手段。ただし**特定の局面（L3以上）でのみ** |
| **独立監査** | **必須** | 条件Cに該当する唯一の分離。歴史・軍事・組織論・AI研究の全てが同じ結論 |

**「AI同士に議論させる」は魅力的に見えるが、費用対効果が悪い。**
必要なのは議論ではなく、**1回の構造化された反論**である。プリモータム3項目（`05`）で十分。

## 10. 本章の結論

1. **「エージェントを増やせば賢くなる」は否定された。** 計算量を統制すると単一エージェントが同等以上。報告された優位の多くは計算量とコンテキスト効果で説明される。
2. **失敗はモデル性能ではなくシステム設計に由来する**（MAST）。プロンプト改善では解決しない。
3. **コンテキスト断片化が中核メカニズム。** 引き継ぎのたびに要約による損失が累積する。「同じことを何度も説明する」はこの人間側の現れ。
4. **エージェント追加が正当化されるのは3条件のみ**: 並列独立探索／コンテキスト隔離／**検証の独立性**。
5. **「別の人格が欲しい」はエージェントを作る理由にならない。** それは指図書の一行で足りる。
6. **最適数は Core 3 ＋ Specialist 4 ＋ System 2 の計9。上限10。** 認知科学・歴史・AI実証の3系統が独立に3〜5に収斂。
7. **Background Systems の多くはLLMではなくスクリプトにすべき。** 速く、安く、確実で、ハルシネーションしない。
8. **忘れる仕組みのないメモリは劣化する。** 図書館に退役の仕組みが必要。
9. **三省制（起草→審査→実行）はL3以上に限定適用する。** 全作業に適用すると唐の政事堂と同じ運命をたどる。
10. **AI同士の議論は不要。必要なのは1回の構造化された反論と、独立した監査である。**
