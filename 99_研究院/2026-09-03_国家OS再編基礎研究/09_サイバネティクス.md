# 09 サイバネティクス — VSM と Ashby の法則

本研究において**最も設計に直結する理論分野**。
サイバネティクスは「制御とコミュニケーションの科学」であり、国家・脳・組織を同じ言語で扱える唯一の枠組みである。

## 1. Wiener — フィードバック制御

[FACT / Evidence: HIGH]
Norbert Wiener (1948) がサイバネティクスを定式化。中核概念は **フィードバック**。

- **ネガティブフィードバック**: 目標値からのずれを検出し、ずれを打ち消す方向に作用する。**安定化**
- **ポジティブフィードバック**: ずれを増幅する。**成長または暴走**
- **フィードフォワード**: ずれが起きる前に、予測に基づいて先回りする

[INTERPRETATION → 国家OSにおける3種のループ]

| ループ | 国家OSでの実装 | 現行 ai-imadaruma での状態 |
|---|---|---|
| ネガティブ（安定化） | 監査・週次レビュー・数字の確認 | 制度としてはあるが、実行頻度が不明 |
| ポジティブ（成長） | 収益 → 再投資 → 収益。学習 → 能力 → 成果 | 弱い。収益が学習に再投資される経路が未定義 |
| ポジティブ（暴走） | 新規事業 → 忙しさ → 新規事業の増加 | **監視されていない。最大のリスク** |
| フィードフォワード | 予測記録・シナリオ・撤退線の事前設定 | ほぼ無い |

[DESIGN]
> **ポジティブフィードバックには必ず制動（ネガティブフィードバック）を対で設計する。**
> 「新規を始める」というポジティブループには、「参入審査」と「定員制」という制動をかける。制動のないポジティブループは必ず暴走する。

**遅れ（delay）の問題** [FACT / Evidence: HIGH]
フィードバックに遅延があると、システムは振動する（オーバーシュート → 修正過剰 → 逆方向のオーバーシュート）。

[INTERPRETATION]
月次でしか数字を見ないと、修正が1ヶ月遅れ、過剰修正を生む。逆に、日次で全指標を見ると雑音に反応して振動する。
**指標ごとに適切な観測周期がある。**

[DESIGN → 指標の観測周期]
| 指標 | 周期 | 理由 |
|---|---|---|
| 体調・睡眠 | 日次 | 変動が速く、遅れが致命的 |
| 実行（今日の一手） | 日次 | 制御対象そのもの |
| 入金・支出 | 週次 | 日次だと雑音が多い |
| パイプライン・返信率 | 週次 | 営業サイクルの粒度 |
| 事業の継続/撤退 | 月次〜四半期 | 短期で判断すると振動する |
| 戦略・資源配分 | 四半期 | 遅すぎる修正を防ぐ下限 |
| 憲法・同一性 | 年次 | 頻繁に変えると同一性が失われる |

## 2. Ashby の必要多様性の法則（Law of Requisite Variety）【最重要】

[FACT / Evidence: HIGH]
W. Ross Ashby (1956)。定式化: **"Only variety can destroy variety."**
> 制御システムが環境を制御するためには、制御システムの取りうる状態数（variety）が、環境の擾乱の状態数以上でなければならない。

[INTERPRETATION → 個人国家の根本問題]

環境の多様性（顧客・市場・SNS・技術・体調・家族・偶発事象）は**膨大**。
制御側の多様性（君主一人の時間と注意）は**極めて限定的**。

**この不等式は、素朴には成立しない。** 個人国家は原理的に統治不能に見える。

しかしAshby自身が2つの解決策を示している。

### 解決策A: Variety Attenuation（多様性の減衰）— 環境側を減らす
環境の擾乱を、制御側に届く前に減らす。

[DESIGN → 実装]
- **やらない戦リスト**: 対応しない領域を明示的に決める（＝環境の一部を無視する）
- **参入審査**: 新しい環境接点を増やさない
- **通知・情報源の削減**: 見る情報の種類を減らす
- **顧客/案件の絞り込み**: 対応する市場セグメントを狭める

> **これが個人国家における最重要戦略である。** 「やらないことを決める」は精神論ではなく、**Ashbyの法則から導かれる数学的要請**である。

### 解決策B: Variety Amplification（多様性の増幅）— 制御側を増やす
制御側の対応能力を増やす。

[DESIGN → 実装]
- **AIエージェント**: 君主の対応能力を増幅する
- **自動化・スクリプト**: 判断なしで処理される範囲を広げる
- **テンプレート・チェックリスト**: 一度作った対応を再利用する
- **習慣**: 実行機能を消費せずに実行される行動を増やす

[INTERPRETATION → 増幅の落とし穴]
> **AIエージェントを増やすことは、確かに多様性の増幅である。しかし、エージェント自体が新たな環境（管理対象）になる。**

エージェントを1体増やすと:
- 増幅される多様性: +1
- 新たに管理すべき多様性: +1（そのエージェントの状態管理、正本、記憶、更新）

**純増分はゼロに近づき、ある点を超えると負になる。** これが「エージェントを増やしても賢くならない」ことのサイバネティクス的説明である（`11`の実証研究と独立に同じ結論に到達）。

[DESIGN]
> **増幅は「エージェント数」ではなく「自動化・テンプレート・習慣」で行え。** これらは管理対象を増やさずに多様性を増やす。
> エージェントは、**管理コストを上回る増幅を確実に生む場合のみ**追加する。

## 3. Viable System Model（VSM）【本章の核心】

[FACT / Evidence: HIGH]
Stafford Beer が Ashby と Wiener を基礎に構築した組織モデル。「生存可能なシステム」が持つべき5つのサブシステムを規定する。再帰的（各S1がそれ自体VSMである）。

### 5つのシステム

| System | 名称 | 機能 | 時間軸 | 問い |
|---|---|---|---|---|
| **S1** | Operations | 実際に価値を生む活動そのもの | 今 | 何を作り、何を売っているか |
| **S2** | Coordination | S1同士の**振動・衝突の抑制**。スケジュール、標準、共通言語 | 日〜週 | S1同士がぶつかっていないか |
| **S3** | Control | S1全体の資源配分と最適化。内部の「今」の管理 | 週〜月 | 資源は正しく配分されているか |
| **S3\*** | Audit | S3の通常報告ラインを**バイパス**した直接監査 | 随時 | 報告は本当か |
| **S4** | Intelligence | **外部と未来**の探索。適応 | 月〜年 | 環境はどう変わるか |
| **S5** | Policy / Identity | 同一性、目的、S3とS4のバランス裁定 | 年〜 | 我々は何者か |

### VSMの2大病理 [FACT / Evidence: HIGH]

Beer が繰り返し強調した失敗パターン。

**病理1: S3–S4のバランス崩壊**
- **S3優位（内向き）**: 日々の運営に埋没し、環境変化を見ない。効率的に間違った方向へ進む
- **S4優位（象牙の塔）**: 未来の構想ばかりで、今日の運営が回らない。研究と計画だけが積み上がる

**S5の最重要機能は、S3とS4のどちらを優先するかを裁定すること。**

**病理2: S2の欠如**
S2（調整）が無いと、S1同士が資源を奪い合い、システムが振動する。S2は最も地味で最も忘れられる。

[INTERPRETATION → 現行 ai-imadaruma の VSM 診断]

| System | 現行の担当 | 診断 |
|---|---|---|
| **S1** | 貿易省（制作・営業）、note運営OS、産業庁のツール群 | **存在する。ただし記録が分散** |
| **S2** | **該当なし** | **欠如。** 日次運用ボード22枚が事実上S2の役割を担おうとして失敗している |
| **S3** | 執行官スマラビ | 存在する |
| **S3\*** | 栄一（事後監査） | 存在する。設計は正しい |
| **S4** | ダ・ヴィンチ、ルパン、アショーカ | **過剰。3体もある** |
| **S5** | 君主＋憲法＋律令府 | 存在する |

**診断結果:**
> **S4が過剰（3体）で、S2が欠如している。** これは Beer の病理1（S4優位＝象牙の塔）と病理2（S2欠如）の**同時発症**である。

症状として予測されること、および実測との照合:
- 研究・調査の成果物が多い → **実測: note調査だけで8ファイル、対話ログでダヴィンチ38KB・アショーカ21KB。一致**
- 実行と収益の記録が薄い → **実測: 04_理財省が2ファイル。一致**
- 日次運用が振動する（ボードが増えては使われなくなる） → **実測: 22枚中約半数が1ヶ月未更新。一致**

**VSM診断が、リポジトリの実測値と3点で一致した。** これは偶然とは考えにくく、構造的な問題であることを強く示唆する。

### VSM の個人国家への適用可否

[INTERPRETATION]
VSMは組織理論だが、**Beer自身が個人への適用を論じており**、後の実務者も自己管理への応用を行っている（`intelligente-organisationen.de` の personal example 等、Tier C）。

適用上の注意:
- S1の「複数の事業単位」が、個人では**時間帯で分割された自分**になる
- S2の「調整」が、個人では**スケジューリングと切り替え規律**になる
- S5の「同一性」が、個人では**文字通りアイデンティティと憲法**になる

**個人国家においてVSMは、そのまま使える。むしろ組織より素直に対応する。**

[DESIGN → VSM を国家OSに写像する]

```
S5  君主 ＋ じぶん憲法 ＋ 第一国家目標
      │  （S3とS4のバランスを裁定する。これがS5の主業務）
      ├──────────────┬──────────────┐
      │              │              │
S4   知              S3  執行代理     S3* 監査
     外部情報            資源配分         独立検証
     図書館              週次の資源決定    君主へ直報
     未来
      │              │
      └──── S2 ──────┘
         調整（規格・時間割・入口の一本化）
              │
S1  ─────────┴──────────────
    商（売る）／匠（作る）／筆（書く）／画（描く）
```

**最重要の設計判断:**
> **S3とS4は必ず別のエージェントにする。同一エージェントに持たせると、必ずどちらかが勝ち、Beerの病理1が発症する。**
> そしてS5（君主）の最も重要な日常業務は、**「今週はS3寄りか、S4寄りか」を決めること**である。

## 4. S2 の設計 — 欠如している機能

[INTERPRETATION]
現行に最も欠けているのがS2。しかしS2は最も分かりにくい。具体的に何をするのか。

[DESIGN → S2の具体的内容]
S2 は「エージェント」ではなく **「規格と時間割」** として実装する。

| S2の要素 | 実装 |
|---|---|
| **共通規格** | 記録フォーマット、命名規則、frontmatterの標準、指図書テンプレート |
| **時間割** | 朝＝実行、夜＝内省、週次＝監査、月次＝国務、四半期＝戦略（`06`のDMN/ECN分離と一致） |
| **入口の一本化** | 全ての入力は受信箱へ。全ての依頼は執行代理へ |
| **衝突の解消** | 同じ時間帯に2つの活動を入れない。優先順位の事前ルール |
| **振動の抑制** | 「一度決めたら◯日は変えない」ルール（例: 事業方針は最低4週間） |

> **S2はエージェントではなく制度である。** ここを間違えて「調整AI」を作ると、エージェントが1体増えるだけで振動は止まらない。

## 5. サイバネティクスから抽出する設計原理

| # | 原理 | 出典 | 実装 |
|---|---|---|---|
| 1 | ポジティブループには必ず制動を対で設計する | Wiener | 参入審査・定員制 |
| 2 | 指標ごとに適切な観測周期がある。速すぎると振動、遅すぎると過剰修正 | Wiener | 観測周期表 |
| 3 | **やらないことを決めるのは数学的要請である** | Ashby | やらない戦リスト・参入審査 |
| 4 | 増幅は自動化・テンプレート・習慣で行う。エージェント増は純増分がゼロに近い | Ashby | エージェント上限 |
| 5 | S1〜S5の5機能は必要。欠けると生存できない | Beer | 組織モデル設計 |
| 6 | **S3とS4は別エージェントに。同一だと必ず病理1が起きる** | Beer | 執行代理と知の分離 |
| 7 | **S3\*（独立監査）はS3の報告ラインをバイパスする** | Beer | 監査は君主へ直報 |
| 8 | **S2は忘れられやすいが不可欠。ただしエージェントではなく制度として実装する** | Beer | 規格・時間割・単一入口 |
| 9 | **S5の主業務はS3とS4のバランス裁定** | Beer | 君主の週次判断 |
| 10 | 再帰性: 各S1もそれ自体VSMである | Beer | 事業ごとにミニ統治構造を持たせる |

## 6. 本章の結論

1. **Ashbyの法則から、「やらないことを決める」は精神論ではなく数学的要請である。** 環境の多様性を減衰させることが、個人国家の第一戦略。
2. **エージェントを増やすことによる多様性増幅は、管理コストの増加で相殺される。** 増幅は自動化・テンプレート・習慣で行う。
3. **現行 ai-imadaruma のVSM診断: S4過剰（3体）＋S2欠如。** Beerの2大病理の同時発症であり、リポジトリの実測値3点と一致する。
4. **S3（執行）とS4（情報・未来）は必ず別エージェントにする。**
5. **S3\*（監査）はS3をバイパスして君主へ直報する。**
6. **S2はエージェントではなく制度（規格・時間割・単一入口）として実装する。** ここを間違えると「調整AI」という無駄なエージェントが生まれる。
7. **君主（S5）の最重要日常業務は、S3とS4のバランス裁定である。** 「今週は稼ぐ週か、備える週か」。

## 補論: 複雑系（Complex Adaptive Systems）

国家・脳・組織はいずれも複雑適応系である。第14項の研究要求に対応する。

[FACT / Evidence: MEDIUM–HIGH]

| 概念 | 内容 | 個人国家への含意 |
|---|---|---|
| **自己組織化** | 中央設計なしに秩序が生まれる | 良い習慣は「設計」より「条件を整える」ことで生じやすい |
| **創発** | 部分の総和にない性質が全体に現れる | 良いエージェント群が良い統治を生むとは限らない（逆も真） |
| **冪則的な事象分布** | 稀だが巨大な事象が存在する | 平均で計画すると、稀な大事象で破綻する |
| **Resilience（回復力）** | 撹乱後に機能を回復する能力 | 縮退運転モード、バッファ（現金・時間・体力） |
| **Antifragility（反脆弱性）** | 撹乱によって強くなる性質（Taleb, Tier C–B） | 小さく失敗して学ぶ実験を意図的に配置する |
| **冗長性 vs 効率** | 冗長は非効率だが破綻に強い | **効率を極限まで上げると脆くなる。予定を100%埋めない** |
| **経路依存性** | 過去の選択が将来の選択肢を制約する | 早期の構造決定が長く効く。だから今の再編が重要 |

[INTERPRETATION → 3つの実務的含意]

**(a) 効率と頑健性はトレードオフである**
予定を100%埋めた週は、1つの想定外で全崩壊する。**70%充填を設計値とする**（クラウゼヴィッツの摩擦と同じ結論）。

**(b) 平均で計画してはいけない**
「月20万円の収入」は、実際には0円の月と40万円の月かもしれない。**中央値と最悪値の両方で計画する。** 最低現金水準はこのために存在する。

**(c) 反脆弱性は「小さく失敗する回数」で買う**
大きく1回賭けると、失敗が致命傷になる。小さく多数試すと、失敗が情報になる。
→ 新規事業は**小さい実験として複数**、大きい投資は**検証後に1つ**。

[DESIGN]
> **国家運営の設計値: 時間充填率70%、実験は小さく複数、投資は検証後に集中。**
