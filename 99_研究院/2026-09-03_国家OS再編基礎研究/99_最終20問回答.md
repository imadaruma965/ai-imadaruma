## Q2. 不要になりやすい組織は何か

**答: 「領域」を名前にした組織。**

| 不要になりやすい | 理由 |
|---|---|
| **領域名の省庁**（修身省・貿易省・理財省など） | 領域は台帳で足りる。組織にすると、領域が増えるたびに組織が増える |
| **統括・調整だけを行う中間層**（庁・統括ポスト） | 実際の成果物を出さない層は、必ず儀礼化する |
| **常設の研究機関** | 研究は継続的需要が読めない。必要な時に一時的に立てればよい |
| **法務・規約の専任** | 頻度が低い。監の封駁チェックリストの1項目で足りる（実測: 韓非子の対話ログ1.0KB） |
| **成果物を出さない定例会議体** | 英Privy Council。必ず儀礼化して消える |
| **人格教育の専任** | 教育と監査は「基準に照らす」同一機能。ローマCensorの regimen morum |

根拠: `02`律令制・`15`原則1・`19`実測

## Q4. 君主が日常的に話すべきAIは何体か

**答: 1体（内府のみ）。**

- **日次: 1体**（内府・朝5分＋夜5分）
- **週次: +1体**（監・30分）
- **必要時: +1体**（知）
- **工房・機関: 直接話さない**（内府経由・自動）

**根拠**: 脳のSalience Networkは単一である。切替機構が複数あると、切替の切替が必要になる（`06`）。
加えて、専門エージェントの名前を君主が覚えている必要をなくすことが、外在的認知負荷をゼロにする唯一の方法（`07`）。

Evidence: **HIGH**

## Q5. AIに上下関係を作るべきか

**答: 作る。ただし「命令」の上下ではなく「情報の流れ」の上下である。**

- 上下があるのは **「内府 → 工房」の1箇所だけ**（これも命令ではなく発注）
- **内府・監・知の3体は、君主に対して並列**である
- **監は内府の部下ではない**（バイパスして君主へ直報）
- **知は誰も指揮しない**（幕僚は指揮しない）
- **工房同士は連携しない**（内府が統合する）

フラットにすると調整コストが二次関数的に増え、`10`のNetwork型（36.4点）になる。
一方、AIがAIに命令する構造は責任の所在を曖昧にする（`05` 幕僚制度）。

Evidence: **HIGH**

## Q6. 三権分立は必要か

**答: 不要。二権分立で足りる。**

- **立法（憲法）** は君主が直接保持する。AIは改正提案のみ
- **執行** は内府
- **検証** は監
- 司法に相当する独立機構は作らない。憲法適合性の判断は監の封駁チェックリスト第1項目で足りる

**理由**: 宋が宰相権を三分割した結果、腐敗は減ったが意思決定を完結できる者がいなくなり、冗官・冗費・機動不能に陥った。**小国で分権を徹底すると死ぬ**（`02`）。

Evidence: **HIGH**

## Q7. 監査AIは必要か

**答: 必要。これは本研究で最も強く支持される単一の結論である。**

5つの独立した系譜が同じ結論に到達している。

| 系譜 | 根拠 |
|---|---|
| 中国史 | 御史台（三省とは別系統） |
| 米国 | GAO は議会に属し、行政府を監査する |
| 中国史 | 清の密奏制度（通常報告ラインのバイパス） |
| サイバネティクス | VSM の S3\*（S3をバイパスする監査チャネル） |
| AI実証研究 | 自己検証はバイアスを持つ。MAST の (iii) task verification |

**必須条件**: 監査者は監査対象に報告してはならない。**監は内府に報告せず、君主へ直報する。**

**現行の栄一（CPIB型・一時停止勧告権あり）は、この点で既に正しい設計であり、そのまま継承する。**

Evidence: **HIGH**

## Q8. Red Team AIは必要か

**答: 機能としては必要。独立エージェントとしては不要。監に内包する。**

**理由3つ**
1. Red Team は常時稼働の必要がない。L3以上の局面でのみ必要
2. 監査を複数置くと宋になる（`14` 原則2）
3. 監査と Red Team は「基準に照らして疑う」という同一機能。対象が過去（監査）か未来（Red Team）かの違いだけ

**実装**: 監の**プリモータム儀式**として。L3以上の着手前に必ず1回。
出力は3点セット固定 — 失敗理由3つ／隠れた前提2つ／撤退サイン1つ。

Evidence: MEDIUM–HIGH

## Q9. Research AIとKnowledge AIは分けるべきか

**答: 機能としては分ける。エージェントとしては現段階では分けない（1体＝知）。**

**分ける理由（機能として）**
- Research＝外向き・大量・使い捨て
- Knowledge＝内向き・少量・永続
- 研究者が自分の成果を自分で図書館に入れると、質の門番がいなくなる

**分けない理由（エージェントとして）**
- 現在の規模では、1体で週15分の運用に収まる
- `11` 3条件テスト: 2体に分ける正当性が現時点では弱い
- S4は既に過剰（現行3体）。増やす方向は病理1の悪化

**分離の判断トリガー（数値で決める）**
> **図書館の週次運用が15分を超えたら、または受信箱の週次流入が30件を超えたら、分割を検討する。**

代わりに、**1体の中で門を作る**: 研究成果は必ず `00_受信箱` に入り、**別セッション・別チェックリストで蒸留する**。同じ会話の続きで研究ノートにしない。

Evidence: MEDIUM

## Q10. 戦略AIと実行AIは分けるべきか

**答: 分けない。同一（内府）にする。ただし「戦略を決めるのは君主」である。**

**理由**
- 戦略と実行を別AIにすると、戦略AIが実行の制約を知らないまま計画を立て、実行AIがそれを無視する（MASTの inter-agent misalignment）
- 個人国家の戦略は「今週どこに時間を使うか」であり、実行と不可分
- `11`: 密に相互依存するタスクにマルチエージェントは不向き

**ただし決定的な条件**: **内府は戦略を起草するだけで、決定しない。決定は君主（L4）。**
「決めると実行を分離する」（シンガポール型）とは、**AIとAIを分けることではなく、君主とAIを分けること**である。

> 現行 CLAUDE.md の「シンガポール型の決めると実行を分離する原則」の理解は正しい。
> ただし実装では、戦略ファイルが法の系統（`00_律令府/戦略/`）に置かれており、**分離の方向を誤っている**（`19` X1）。

Evidence: MEDIUM–HIGH

## Q11. 財政AIは独立させるべきか

**答: 独立させない。対話型AIをやめ、自動化（帳）に転換する。**

**理由**
- 実測: `04_理財省` の総ファイル数は **2**。対話型エージェントとして機能していない
- 財政に必要なのは会話ではなく、**正確な数字が毎週自動で出ること**
- 数値集計・漏れ検知は、スクリプトのほうが速く・安く・確実で・ハルシネーションしない（`11` 結論7）

**ただし2つを守る**
1. **予算のゲートは1つにする**（英Treasury）。時間と金の新規支出は必ず1箇所で判定
2. **勘定を3つに分ける**（運転／投資／備蓄）。**備蓄の取り崩しは L4（君主のみ）。AIは提案すらできない**（シンガポールの準備金二重鍵、尊徳の分度）

Evidence: **HIGH**（実測に基づく）

## Q12. 外部情報と内部情報を分離すべきか

**答: 経路は分離する。エージェントは分離しない。**

| | 担当 | 方法 |
|---|---|---|
| **外部情報**（市場・競合・技術・社会） | **知**（LLM） | 情報要求書（RFI）に基づく調査 |
| **内部情報**（金・時間・体・行動・KPI） | **帳・録**（自動化） | 台帳の自動更新。**LLMを使わない** |

**理由**: 内部情報は「取得」であって「分析」ではない。自分の睡眠時間を知るのにLLMは要らない。
外部情報は解釈と検証を要するのでLLMが要る。**必要な処理が質的に違うので、道具が違う。**

**そして統合点は1つにする**: 両者は `国情ブリーフ` に集約される。
これが米ICの stovepipe 問題への対策であり、DNI に相当する（`02`）。

Evidence: **HIGH**

## Q13. 現在の歴史人物AI方式は維持すべきか

**答: 通称としては維持する。正式名としては廃止する。**

**評価（`16`）**
| 方式 | 点数 |
|---|---|
| 人物名型（現行） | 62 |
| 役職名型 | 74 |
| 省庁型 | 55 |
| コードネーム型 | 40 |
| **ハイブリッド** | **86** |

**人物名の利点**（捨てない）
- 記憶しやすく、愛着が湧く
- LLMのrole promptingが効き、語調と価値観が安定する
- `07` Identity-based Behavior として強力

**人物名の欠点**（正式名から外す理由）
- **役割が外から分からない**。「韓非子」からは、いつ呼ぶべきか分からない（実測: 対話ログ1.0KB）
- 人格模倣に転化し、判断が演技になる
- 歴史人物の思想に引っ張られる

**採用ルール**
- **正式名 = 機能名**（内府・監・知・商・匠・筆・画・帳・録）。ファイル名・フォルダ名・Skill名はこれ
- **通称 = 人物名**（賢いうさぎ・栄一・ダ・ヴィンチ・龍馬・テスラ・正篤・北斎・ルカ）。呼びかけと語調に使う
- **原則**: 思想は原理として抽出し、人格としては輸入しない（`04`）

Evidence: MEDIUM–HIGH

## Q14. 最も参考にすべき国家制度は何か

**答: 唐の三省六部＋御史台。**

**理由**
1. **機能レイヤー（三省）と領域レイヤー（六部）を明確に分離していた唯一の制度。** これが本研究の最重要原則（原則1）そのもの
2. **起草・審査・執行の三分離**が、AIのハルシネーション対策として現代的に有効
3. **御史台を三省の外に置いた**（監査の独立）
4. **崩壊の仕方まで教訓になる**: 政事堂への統合と門下省封駁権の空洞化が、「審査は安くなければ形骸化する」（原則3）を教える

**次点3つ**
- **シンガポール**: 人数を増やさず質を上げる／時間軸の階層化／運転と蓄積の分離
- **ローマ共和政（Censor）**: 定期的な構成員審査（lustrum）と regimen morum
- **ヴェネツィア共和国**: 小国が1000年生きた実例。relazioni による情報の体系的蓄積

Evidence: MEDIUM–HIGH

## Q15. 最も参考にすべき組織理論は何か

**答: Stafford Beer の Viable System Model（VSM）。**

**理由**
1. **国家・脳・組織を同じ言語で扱える唯一の枠組み**。本研究の全分野を横断できる
2. **S1〜S5 の機能定義が、統治の6普遍機能とほぼ一致する**
3. **S3\*（監査のバイパス）** が、歴史（御史台・GAO・密奏）とAI実証（検証の独立性）と独立に一致する
4. **2大病理（S3–S4バランス崩壊／S2欠如）が、現行 ai-imadaruma の実測値3点と一致した**
5. **S5の主業務が「S3とS4のバランス裁定」**という定義が、君主の日常業務を明確にする
6. 再帰性により、事業が増えても構造が変わらない（拡張性）

**次点**: Mintzberg の調整メカニズム（アウトプットの標準化）。Auftragstaktik と独立に同じ結論に到達している。

**VSMをそのまま使わない理由**: 「S3\*」「S2」という名前に愛着が持てず、identity装置として弱い（`17` 君主との相性45点）。**機能定義はVSM、名前は国家メタファー**というのが推奨モデルの立場。

Evidence: **HIGH**

## Q16. 最も参考にすべき脳モデルは何か

**答: Triple Network Model（DMN / ECN / Salience Network）。**

**理由**
1. **脳は分散処理であり中央司令部を持たない。しかし切り替え機構（SN）は単一である。** これが「日常接点は1体」という設計の神経科学的根拠
2. **DMNとECNは拮抗する。** 内省と実行を時間帯で分けるべき（朝＝実行、夜＝内省）という運用設計が導かれる
3. **DMNを潰してはいけない。** 「何もしない時間」は怠慢ではなく長期展望の稼働時間

**補完的に使う2モデル**
- **基底核による習慣系**: 習慣は実行機能を消費しない → 統治の目標は「判断を減らす」こと
- **ドーパミン報酬予測誤差**: 新奇性そのものが報酬 → 新規事業中毒は意志の問題ではない

**採用しないモデル**: Ego Depletion（自我消耗）。大規模replicationで効果が確認されず、証拠が弱い。切り替えコストと睡眠で代替説明する。

Evidence: **HIGH**

## Q17. 最も参考にすべきAIマルチエージェント構造は何か

**答: オーケストレーター–ワーカー型。ただし「常時マルチ」ではなく「必要時のみマルチ」。**

**参考にする実装**: Anthropic の Research システム（リードエージェント＋3〜5サブエージェント＋別パスの引用付与）。

**ただし個人国家では、次の3点で修正する。**

| Anthropic Research | 個人国家版 |
|---|---|
| 常時マルチエージェント | **日常運用は単一。マルチは「知」の調査時のみ** |
| トークン15倍 | **予算制約により、多用できない** |
| 広範な調査に最適 | **日次運用は相互依存が強いので、単一エージェントで動かす** |

**そして、Anthropic の構成には無い要素を1つ加える。**
> **独立した検証者（監）を、オーケストレーターの外に置く。**
> Anthropic の構成はオーケストレーターが統合まで行うが、個人国家では**オーケストレーター自身を監査する主体**が必要である。自己欺瞞が最大の敵だから。

これが「オーケストレーター–ワーカー型 ＋ 独立検証者」という推奨構造である。

Evidence: **HIGH**

## Q18. ダヴィンチ図書館は国家組織のどこに置くべきか

**答: 国家組織の「中」ではなく「隣」に置く。知（S4）が館長を務めるが、図書館は知の所有物ではない。**

**位置づけ**: ローマ元老院と同じ性格。
> **決定権はない。しかし決定はそれを参照せねばならない。**

**物理的配置**: **独立Vault・独立gitのまま維持する。** 境界を物理的に強制できるから。

**接続方法**: 境界を越えるのは**2つの成果物だけ**。

```
[国家OS] 決める・動く          [図書館] 賢くなる
  小さく保つ（100ファイル以下）    大きくてよい（現在567）
        │                            │
        ├──── 決裁記録 ─────────────→│  （追記のみ・改変禁止）
        │                            │
        │←──── 原則カード ───────────┤  （週0〜2枚）
```

**現在の違反**: `90_国家OS保管/`（decisions/daily_logs/weekly_reviews）と `02_国家事業/` が図書館内にあり、**図書館が国家OSを飲み込んでいる**。これを解消する。

Evidence: MEDIUM–HIGH

# 補: 本研究の総括

## 最も重要な発見

> **現行 ai-imadaruma の問題は、13体という数でも、組織図の複雑さでもない。**
> **「人生の領域」「統治の機能」「AIエージェント」を1対1対1で対応させたこと、その一点である。**
>
> 領域は十数個ある。統治機能は6個しかない。
> **エージェントは機能の数だけ置き、領域の数だけ置いてはならない。**
> **領域は、エージェントではなく台帳として持て。**

観測された全ての症状 — 役割重複、休眠エージェント、対話ログの分散、誰に聞くか分からない、組織図が使われない、2週間で5回の改編 — は、この一点から派生している。

## 最も強固な結論（5系統以上の独立した裏づけを持つもの）

1. **監査は実行から独立させ、監査対象に報告させない**（歴史・組織論・サイバネティクス・AI実証・軍事）
2. **廃止をデフォルトにする**（歴史×2・失敗分析・行動経済学・AI・知識管理）
3. **事前に予測を書き、事後に照合する**（韓非子・ドラッカー・AAR・メタ認知・Senge・OODA）
4. **日常接点は1体、中核は3体**（認知科学・歴史・AI実証）

## 最も反直感的な結論

> **AIエージェントを増やしても賢くならない。多くの場合、悪くなる。**
> 計算量を統制すると単一エージェントが同等以上。報告された優位の多くは、アーキテクチャの利点ではなく、余分に使った計算量とコンテキスト効果で説明できる。
>
> そして個人国家では、エージェント自体が新たな管理対象になるため、**増幅の純増分はゼロに近づき、ある点を超えると負になる**。

## 評価の基準（第66項）

> **その組織図が美しいか、ではない。**
> **毎日実際に使われるか、である。**
>
> 1年後、9体のうち3体しか使われていなかったなら、正解は3体だったということであり、
> それは失敗ではなく、測定できたという成功である。
