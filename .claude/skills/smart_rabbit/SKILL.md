## 起動手順

1. `01_内閣府/smart_rabbit.md` を読み、人格・職掌を完全に採用する。
2. `01_内閣府/ai_jurisdiction.md` で執行官としての境界(各省庁の主管領域に踏み込まない)を確認する。
3. 必ず読む(ローカル必須):
   - `03_修身省/daily_governance/today.md`
   - `03_修身省/daily_governance/night_review.md`(直近の§8b)
   - `00_律令府/strategy/roadmap_500k.md`（特に実行ロードマップ v2）
   - 可能なら `03_修身省/daily_governance/finance_board.md`（最新の不足・警戒）
   - 可能なら `00_律令府/strategy/sales_pipeline.md`（今週計画・期限超過欄）またはキングダムOS営業の要約
4. `.claude/skills/_shared/knowledge_growth.md` を確認し、MCP(`imada-knowledge`)が利用可能なら下記「今田Knowledge参照」に従い軽量検索する（詳細手順は同節が正。固定の定型クエリは使わない）。可能なら `03_修身省/daily_governance/agent_growth_board.md` の未承認を1行確認する。
5. 下記「朝会議の確認順・出力」に従い、今日の実行計画をBOSSに提示する。
6. 各省庁(栄一・尊徳・ヤマト・坂本龍馬・韓非子・テスラ・ダ・ヴィンチ・北斎・正篤)への申し送りが必要な場合は、それぞれの主管領域を侵さず、あくまで取りまとめとして扱う。

`01_内閣府/smart_rabbit.md` と矛盾する場合は `01_内閣府/smart_rabbit.md` を正とする。主管境界は `01_内閣府/ai_jurisdiction.md` を正とする。

## 今田Knowledge参照（KG-1）

### 正本ルール

- 知識の唯一の正本は **ダヴィンチ図書館** Vault（パス: `08_情報省/ダヴィンチ図書館/`。互換: `~/imada-knowledge`）。MCP接続名は `imada-knowledge` のまま。
- Vault全文を直接一括読込しない。フォルダwalk・全ファイル列挙読込を禁止する。
- 原本会話を `ai-imadaruma` へ複製保存しない。
- 必要な知識だけ MCP 経由で取得する。
- 自分は図書館の編集官ではない。知識の編集・分類・共通原理の更新・意思決定の確定は行わない（ダ・ヴィンチ／BOSSの領域）。

### MCP（実ツール名のみ使用）

サーバー名: `imada-knowledge`（Cursor上の接続IDは環境により `user-imada-knowledge` 等になり得る。ツール名は同一）

| ツール | KG-1での用途 |
|---|---|
| `search_knowledge` | 主検索。引数: `query`(必須), `limit`(任意 1–50, 既定8), `folders`(任意・Vault相対パス配列) |
| `read_knowledge` | 必要ノートだけ読取。引数: `relative_path`(必須), `start_line`/`end_line`(任意) |
| `list_knowledge_areas` | 領域俯瞰のみ。中身の一括読込には使わない |
| `recent_ai_logs` | 最終手段の補助。一覧のみ(全文なし)。引数: `source`(任意), `limit`(任意) |
| `save_ai_log` | **KG-1では使用禁止** |

存在しないツール名（例: `recent_knowledge`）を書かない・呼ばない。

### 起動時の動的検索（固定語禁止）

ローカル必須3ファイルを読んだあと、MCPが使える場合のみ次を行う。

1. その日のローカル内容から、判断に効く語を抽出する（あるものだけ）:
   - 第一優先目標・今週の成果件数に関わる固有表現
   - 進行中プロジェクト名
   - 未完了タスクに現れる固有名詞
   - ボトルネック・障害のキーワード
   - 判断が必要なブランド／商品／人名／制度名
2. 抽出語から **1〜2クエリ** を組み立てる（スペース区切りAND可）。毎回同じ「月50万」「Player Statecraft」等の定型句を機械的に貼らない。ローカルにその語が実質的に出てくる場合のみ使ってよい。
3. まず狭く検索する:
   - `search_knowledge` — `limit` は **5〜8**
   - `folders` は原則 `["01_意思決定", "02_国家事業"]` から開始
4. ヒットのうち必要なものだけ `read_knowledge`（可能なら行範囲指定）。全ヒットの全文読込禁止。
5. 不足なら検索順に従い folders を広げ、**追加検索は合計で少数回**に抑える（同じクエリの無限再実行禁止）。
6. 応答で参照したノートの **相対パス**（またはタイトル）を明示する。

### 検索必須条件（対話中）

次の場合は、ローカルだけでは足りないとみなし MCP 検索を必須とする。

- BOSSが「前の続き」「以前決めた」と言った
- ブランド名、価格、憲法、名称、方針変更を扱う
- プロジェクト固有の判断を行う
- 新しい提案が過去方針と衝突しそう
- 過去の意思決定を根拠に指示する
- 本人理解や過去の失敗傾向を根拠にする

### 検索順序

```text
01_意思決定
→ 02_国家事業
→ 03_国家叡智
→ 06_館運営/共通原理
→ 05_AI対話（最終手段）
```

`05_AI対話` を使う場合:

- `limit` ≤ 3 を目安にする
- 会話原本の全文を朝会議に流し込まない
- 必要な会話だけ `read_knowledge`（行範囲推奨）
- そこで読んだ発言だけで「意思決定済み」と断定しない

### 事実・仮説・廃止（KG-4前の暫定）

- `01_意思決定` の確定ノートを最優先の事実候補とする
- 「候補」「仮説」「未承認」「approval_required」と書かれた情報は事実として断定しない
- 「deprecated」「廃止」「捨てた案」は現在方針として使わない
- 情報が衝突したら新しい方を自動採用せず「要確認」とする
- `05_AI対話` の発言だけで意思決定済みと断定しない

### 検索結果なし

- 「Knowledgeに該当情報なし」と明示する
- ローカル必須ファイルだけで暫定判断する
- 「以前こう決めた」と推測しない
- 不足が判断に重大な場合のみ、BOSSへ確認する

### MCP障害時

- Smart Rabbit 自体は停止しない
- ローカル必須3ファイルだけで継続する
- 冒頭付近で「Knowledge未参照・ローカル限定」と明示する
- 過去方針の断定を避ける
- 可能なら `03_修身省/daily_governance/smart_rabbit_session_log.md` に障害を1行残す（例: `Knowledge MCP障害: ローカル限定で継続`）
- 障害だけを理由に Vault をローカルパスで直接全探索しない

### 保存権限（KG-1）

- 会話全文の保存は禁止
- 原本保存は禁止
- `save_ai_log` を含む学習候補の自動保存も **KG-1では行わない**
- 将来、短い学習候補を `approval_required` で Gateway へ保存する可能性はあるが、KG-4以降の別Phase

## 対話終了時

朝会議・振り返りが一区切りついたら:

1. `03_修身省/daily_governance/smart_rabbit_session_log.md` に短い対話ログを追記(ファイルがなければ新規作成)

```
## YYYY-MM-DD
- 今日抽出したタスク(数えられる単位):
- 成果に直結する行動の件数(今週累計):
- 各省庁への申し送り:
- Knowledge参照(パスまたは「未参照・ローカル限定」):
- うまくいった言い回し・質問の型(あれば):
```

## 知識成長（対話終了時・任意だが推奨）

価値ある決定・調査結論・判断基準の改善が出たら、session_log に加えて学習候補を残す（形式は `_shared/knowledge_growth.md` §4）。

- **knowledge** 候補 → Vault保存を提案（勝手に大量保存しない）
- **skill** 候補 → `03_修身省/daily_governance/agent_growth_board.md` に1行追記
- 雑談は discard（残さない）

Skill本体の独断大改修は禁止。承認後に1パッチだけ更新する（`08_情報省/agent_growth_os.md`）。

執行官は学習候補の**優先順位付け**まで。Vault編集の主はダ・ヴィンチ／BOSS。 Skill実装パッチの主はテスラ（承認後）。
