## 3. 抽出する（5種類だけ）

| 種類 | 条件 | 例 |
|---|---|---|
| **決定** | **BOSSが明示的に決めたもの**（「決定」「これでいく」「確定」「OK」「採用」、またはAIの提案への明確な同意） | プロフィール99字版を確定 |
| **訂正** | BOSSの指摘で覆った判断、AIが誤りを認めたもの | 「才能→特性」ルールを撤回 |
| **原則** | 次から使える判断基準・やり方 | 同じ画像へのAI編集は三回まで |
| **事実** | BOSSの経歴・数字・日付・固有名 | メンタルコーチ10年 |
| **持ち越し** | 決まっていない・後でやると言ったもの | 市松模様の意味は未定義 |

**AIが提案しただけで、BOSSが同意していないものは「決定」にしない。**雑談・一度きりの作業は捨てる。

## 4. 反映先を決めて、反映済みか確かめる

| 話題 | 反映先 |
|---|---|
| アカウント名・プロフィール・口調・キャラクター性 | `00_律令府/戦略/賢いうさぎブランド/キャラクター正本_賢いうさぎ_2026-09-09.md` |
| ブランドのLOCK・尖らせ方針・法的な線 | `99_研究院/2026-09-03_賢いうさぎブランド転換研究/17_BRAND_LOCK_REVISION_2026-09-10.md` |
| ビジュアルの世界観・画風・記号の意味 | `03_貿易省/文化庁/賢いうさぎ_ビジュアル資産/キャラマスター/世界観正本_v1.md` |
| 個別の画像制作 | `03_貿易省/文化庁/賢いうさぎ_ビジュアル資産/` の該当する発注書 |
| X投稿の型 | `03_貿易省/文化庁/X投稿型.md` |
| BOSSの経歴・対外プロフィール | `01_内閣府/対外プロフィール/` |
| 戦略・ロードマップ・商品・価格 | `00_律令府/戦略/` 配下の該当正本（**提案のみ。栄一の点検対象と明記**） |
| 人格の振る舞い・失敗・判断基準 | `02_修身省/日次運用/成長ボード.md`（skill候補） |
| 再利用できる調査結論・原理 | `02_修身省/日次運用/成長ボード.md`（knowledge候補） |
| どれにも当たらない | `反映待ち.md` の「振り分け不明」 |

各項目について反映先を `grep` し、**すでに書かれているか**を確かめる。

- 書かれている → **反映済み**
- より新しい決定で上書きされている → **置き換え済み**（反映しない）
- 書かれていない → **未反映**

## 5. 書く

1. **ダイジェスト** `05_情報省/学習ループ/ダイジェスト/YYYY-MM-DD.md`（実行日。同日のファイルがあれば追記）

```markdown
# 学習ダイジェスト YYYY-MM-DD
- 読んだ会話: N件（期間 … 〜 …）／図書館の会話: N件
## 決定（反映済み N／未反映 N）
- [反映済み] … → 反映先
- [未反映] … → 反映待ち #番号
## 訂正
## 原則
## 事実
## 持ち越し
```

2. **反映待ち.md** の「未承認」表に、未反映の項目を1行ずつ追加する。番号は通し番号。**根拠欄にはBOSSの発言を30字以内で引用**し、会話IDの先頭8桁と日時を付ける。
3. **成長ボード.md** の「未承認」表に、人格の学び（skill）と再利用知識（knowledge）を追加する。
4. 対話ログ（`00_律令府/戦略/対話ログ/<人格>.md`）は、人格が話したのに記録が一件も無い日だけ、短く補記する。

## 6. 正本の本文

**正本の本文は直接書き換えない。**変更案を `反映待ち.md` に書くだけにする。
（全自動へ切り替える場合：この節を「未反映の決定は、反映先の正本に直接反映し、反映待ち.md には適用済みとして記録する」に書き換える。BOSSの指示がある場合のみ。）

## 7. 記録を進める

```bash
python3 05_情報省/学習ループ/extract_new_turns.py commit
```

**§5 を書き終えてから実行する。**途中で失敗したら commit しない（次回、同じ範囲をもう一度読む）。

ダイジェストに「週次」節を足し、次を書く。
